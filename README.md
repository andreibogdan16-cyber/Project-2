For this course, I am including artifacts from both Project One and Project Two in my GitHub portfolio. From Project One, I included the contact service files: Contact.java, ContactService.java, ContactTest.java, and ContactServiceTest.java. How can I ensure that my code, program, or software is functional and secure?

I can ensure that my code is functional by carefully reviewing the software requirements and writing tests that verify each required feature. In Project One, I used unit testing to check that the contact service worked correctly, including adding, deleting, and updating contact records. I also tested invalid inputs to make sure the program handled errors properly. This helped confirm that the program behaved as expected under both normal and incorrect conditions.

To help ensure security, I need to validate user input, protect data from being changed incorrectly, and avoid allowing invalid values into the system. For example, the contact service required limits on fields such as contact ID, first name, last name, phone number, and address. By enforcing these limits and testing them, I reduced the chance of bad data entering the program. Secure software development also requires regular testing, code review, and awareness of possible risks.

How do I interpret user needs and incorporate them into a program?

I interpret user needs by first identifying the requirements and understanding what the software must do for the user. In this course, the requirements described what information the contact service needed to store and what actions the system had to support. I used those requirements to decide what classes, methods, and tests were needed.

After identifying the user needs, I incorporated them into the program by designing features that matched the requirements. For example, users needed the ability to create, update, and delete contacts. I built the contact service around those needs and created tests to verify that each function worked correctly. This showed me that user needs should guide both the design of the software and the testing process.

How do I approach designing software?

My approach to designing software is to begin with the requirements, break the problem into smaller parts, and then create a structure that is easy to understand, test, and maintain. For Project One, I separated the contact object from the contact service so that the data and the service logic were organized clearly. This made the program easier to test and easier to modify.

I also learned that testing should be considered during the design process, not only after the code is finished. Writing unit tests helped me think more carefully about how the program should behave and what edge cases needed to be handled. In the future, I will continue using this approach by planning the design, writing clean code, testing often, and reviewing the program against the original requirements.
